# AHN'S Plastic Surgery

> **브랜드의 첫인상부터 진료 정보 탐색까지, 사용자 경험을 중심으로 설계한 성형외과 웹사이트 리뉴얼 프로젝트**

**Next.js 기반의 반응형 웹사이트**로, 브랜드 아이덴티티를 표현하는 인터랙션과 사용자가 정보를 쉽게 찾을 수 있는 정보 구조를 함께 고민했습니다. 일반 사용자 페이지뿐 아니라 콘텐츠 관리, 다국어 표시, 상담·예약 등 실제 서비스 운영에 필요한 흐름까지 고려해 개발했습니다.

[🌐 발표용 데모 보기](http://heartbreakkid.co.kr/group/three/1/)

> **데모 안내**: 위 링크는 Cafe24에 배포한 **정적 프론트엔드 발표용 버전**입니다. 백엔드·데이터베이스 연동이 필요한 로그인, 소셜 로그인, 상담·예약 및 관리자 기능 등은 데모에서 정상 작동하지 않을 수 있습니다. 실제 서비스 배포 상태와 정적 데모의 기능 범위는 구분해 확인해 주세요.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트 | AHN'S 성형외과 웹사이트 리뉴얼 |
| 목적 | 브랜드 이미지 개선, 사용자 탐색 경험 개선, 콘텐츠 관리 구조 확장 |

### 해결하고자 한 문제

성형외과 웹사이트는 단순히 시술 목록을 보여주는 것에 그치지 않고, **신뢰할 수 있는 브랜드 경험**과 **필요한 정보를 빠르게 찾는 사용성**을 동시에 제공해야 합니다.

이를 위해 다음 세 가지를 핵심 목표로 설정했습니다.

1. **일관된 브랜드 경험**: 타이포그래피, 이미지, 컬러, 전환 효과를 통일해 첫인상부터 상세 페이지까지 시각적 흐름을 유지합니다.
2. **명확한 정보 탐색**: 시술 카테고리, 병원 소개, 안전 정보, 커뮤니티 등을 역할에 맞게 구분해 사용자가 원하는 정보를 찾기 쉽게 구성합니다.
3. **운영 확장성 고려**: 다국어 처리, 관리자 콘텐츠, 상담·예약 등 운영 데이터를 화면과 분리하는 구조를 고려합니다.

## 4. UI/UX 설계에서 중요하게 생각한 점

### 4-1. 첫 화면의 인상과 탐색성을 함께 설계

첫 화면에서는 브랜드 분위기를 전달하되, 시술 정보를 찾으려는 사용자의 행동을 방해하지 않도록 고민했습니다. 브랜드 Intro에는 건너뛰기 동작을 두었고, Hero 이후에는 카테고리 및 주요 콘텐츠가 자연스럽게 이어지도록 구성했습니다.

### 4-2. 인터랙션에도 명확한 목적 부여

애니메이션을 단순한 장식이 아니라 **사용자의 시선과 콘텐츠 읽는 순서를 안내하는 수단**으로 사용하려고 했습니다.

- **GSAP Timeline**: 텍스트, 이미지, 보조 요소의 등장 순서를 제어합니다.
- **ScrollTrigger**: 사용자의 스크롤 진행에 맞춰 콘텐츠가 드러나도록 구성합니다.
- **`useRef`**: 애니메이션 대상 DOM 노드와 GSAP 타임라인을 참조합니다.
- **`useEffect`**: 브라우저에서만 가능한 애니메이션 초기화, 이벤트 등록 및 정리 작업을 처리합니다.
- **접근성 고려**: Intro 건너뛰기, 키보드 조작, `prefers-reduced-motion` 대응을 반영했습니다.

### 4-3. 화면 크기와 언어 길이 변화 고려

반응형 화면에서 이미지 배치와 텍스트 가독성을 고려했습니다. 또한 다국어 UI는 단순 번역뿐 아니라 언어별 문장 길이가 달라진다는 점을 고려해 컴포넌트 구조와 콘텐츠를 분리했습니다.

## 5. 프론트엔드 구조

아래는 주요 화면과 역할을 설명하기 위한 **대표 구조**입니다. 전체 디렉터리 트리를 그대로 옮긴 것은 아닙니다.

```text
src/
├── app/                  # Next.js 라우트 및 페이지
├── components/
│   ├── home/             # 메인 페이지 섹션 및 Hero
│   ├── intro/            # 브랜드 Intro 애니메이션
│   ├── auth/             # 로그인 모달·소셜 로그인 UI
│   └── ...               # 공통 UI 및 페이지별 컴포넌트
├── i18n/                 # locale 및 경로 처리
└── lib/                  # API 설정, 데이터 접근, SEO 유틸리티 등
```

**구성 원칙**: 페이지는 화면의 조합을 담당하고, 반복되는 UI와 동작은 컴포넌트로 분리하며, 번역 리소스와 API 처리 로직은 가능한 범위에서 별도 계층으로 관리합니다.

## 6. 개발 과정에서 마주한 문제와 해결 접근

### 6-1. 서버 렌더링과 정적 배포 환경의 차이

**문제**: 서버에서 요청 헤더를 확인해 Intro 표시 여부를 결정하던 로직이 정적 내보내기 환경에서는 그대로 동작하지 않았습니다.

**접근**: 서버 요청 정보에 의존하는 로직과 정적 데모용 진입 판별 로직을 구분했습니다. 브라우저의 navigation 정보와 referrer는 사용할 수 있지만, 이를 통해 모든 이동 상황을 완벽하게 구분할 수는 없다는 제약도 확인했습니다.

**배운 점**: 화면이 같더라도 **서버 렌더링과 정적 호스팅은 사용할 수 있는 정보 및 실행 시점이 다르다**는 사실을 체감했습니다.

### 6-2. Intro의 일시적인 깜빡임

**문제**: 새로고침 시 정적 HTML에서 Intro가 먼저 나타난 뒤 React 초기화 과정에서 즉시 사라지는 현상이 발생했습니다.

**접근**: 초기 렌더 상태와 브라우저에서 판별하는 진입 조건을 분리해, 표시 여부가 결정되기 전 불필요한 화면 노출을 줄이는 방향으로 개선했습니다.

**배운 점**: 애니메이션의 완성도는 효과 자체뿐 아니라 **초기 렌더링, hydration, 상태 전환 시점**에 의해 좌우됩니다.

### 6-3. 다국어 콘텐츠의 누락과 데이터 구조 문제

**문제**: 일부 공통 컴포넌트와 관리자 입력 콘텐츠에서 번역 누락이 있었고, 서버 데이터 조회 및 DB 제약 조건과 관련된 오류도 경험했습니다.

**접근**: 번역 키와 컴포넌트 연결 상태를 점검하고, API 응답 필드와 DB 제약 조건을 함께 확인하는 방식으로 원인을 추적했습니다.

**배운 점**: 다국어 기능은 텍스트만 교체하는 작업이 아니라 **프론트엔드, API, DB 구조가 함께 맞아야 하는 기능**임을 알게 됐습니다.

### 6-4. 실제 사용자 흐름에서 발생하는 예외

**문제**: 회원가입·비밀번호 찾기 등 일부 화면에서 로그인 페이지 이동과 로그인 모달 호출 방식이 섞이면서 사용자 흐름의 일관성이 떨어질 수 있었습니다.

**접근**: 로그인 모달을 여는 공통 동작과 페이지 이동 정책을 분리해 관리하는 방향을 검토했습니다.

**배운 점**: 개별 화면이 정상 작동하는 것만으로는 충분하지 않고, **화면 사이의 이동과 상태 유지까지 포함해 UX를 검증해야 한다**는 점을 배웠습니다.

## 7. 실행 방법

### 프론트엔드

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`으로 접속합니다.

실제 데이터가 필요한 화면은 별도로 실행한 API 서버 및 환경 변수 설정이 필요합니다. 저장소의 `.env.example`이 있다면 해당 안내에 맞춰 개인별 로컬 환경을 구성해 주세요. **실제 API 키, DB 비밀번호 및 OAuth 비밀값은 GitHub에 커밋하지 않습니다.**

### 발표용 데모의 특성

발표용 사이트는 정적 파일을 Cafe24에 업로드한 버전입니다. 서버 API가 필요한 기능은 로컬 개발 환경이나 백엔드가 연결된 환경에서 별도로 검증해야 합니다.

## 9. 프로젝트를 통해 얻은 경험

이 프로젝트에서 가장 크게 배운 것은 **좋은 프론트엔드는 화면을 아름답게 만드는 일과 사용자가 불편 없이 목적을 달성하도록 만드는 일을 함께 해야 한다**는 점입니다.

처음에는 레이아웃과 인터랙션 구현에 집중했지만, 작업이 진행될수록 화면이 보여지는 시점, 사용자가 이동하는 경로, API 오류가 발생했을 때의 처리, 언어가 바뀌었을 때의 레이아웃까지 고려해야 한다는 것을 알게 됐습니다.

특히 다음과 같은 경험이 의미 있었습니다.

1. **디자인을 코드로 구체화하는 경험**: 타이포그래피와 여백, 이미지, 애니메이션의 관계를 조정하며 의도한 브랜드 분위기를 실제 화면으로 구현했습니다.
2. **React의 렌더링 흐름을 이해하는 경험**: `useState`, `useRef`, `useEffect`를 실제 UI와 애니메이션에 적용하며 상태·DOM 참조·생명주기가 서로 어떻게 연결되는지 학습했습니다.
3. **문제를 재현하고 원인을 추적하는 경험**: Intro 깜빡임, 다국어 누락, API/DB 오류 등을 통해 증상만 수정하기보다 어느 계층에서 문제가 발생하는지 확인하는 습관을 익혔습니다.
4. **서비스 전체 흐름을 바라보는 경험**: 사용자 페이지뿐 아니라 관리자, 다국어, 상담·예약, 인증 흐름을 함께 고려하며 컴포넌트 하나가 전체 사용자 경험에 미치는 영향을 배웠습니다.
5. **개발 환경과 배포 환경의 차이를 이해하는 경험**: Next.js의 서버 기능과 정적 배포의 제약을 구분하며, 배포 방식에 따라 설계와 테스트 방법이 달라져야 한다는 점을 익혔습니다.

아직 개선할 부분도 남아 있지만, 이 프로젝트를 통해 **기능을 구현하는 것에서 나아가 왜 그렇게 구현했는지 설명하고, 문제가 생겼을 때 근거를 바탕으로 개선하는 개발자**로 성장하는 방향을 배웠습니다.
