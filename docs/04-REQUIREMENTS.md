# 핵심 기능 명세 및 요구사항 정의서 (면접용 축약본)

> 실제 협업 과정에서 작성된 모든 원본 WBS/요구사항 문서를 대체하지 않습니다. 면접관이 서비스 범위와 구현상의 고려 사항을 빠르게 파악할 수 있도록 **요구사항·수용 기준·검증 상태**만 추렸습니다.

## 3. 핵심 화면 사용자 시나리오

### 시나리오 A — 외국어 사용자의 정보 탐색

1. 첫 화면에서 언어를 선택합니다.
2. 헤더·카테고리·시술 페이지의 UI 문구가 선택 언어로 바뀝니다.
3. 운영 콘텐츠는 해당 언어의 CMS 번역을 표시합니다.
4. 번역 데이터가 없다면 명시된 fallback 정책에 따라 처리합니다. (정책은 실제 코드 확인 필요)
5. 다른 페이지로 이동해도 locale이 유지되는지 검증합니다.

### 시나리오 B — 모션과 페이지 이동

1. 허용된 초기 진입 상황에서만 Intro가 재생됩니다.
2. Skip/Escape 또는 타임라인 완료 시 Intro가 사라집니다.
3. Hero가 적절한 시점에 표시·작동합니다.
4. 새로고침·뒤로가기·내부 이동에 따른 재생 정책을 검증합니다.
5. ScrollTrigger가 언마운트 때 DOM과 이벤트를 복원합니다.

### 시나리오 C — 관리자 번역 콘텐츠 수정

1. 운영자가 콘텐츠 소스를 선택합니다.
2. 언어별 값을 수정해 저장 요청을 보냅니다.
3. API는 타입 및 필드를 확인합니다.
4. Oracle DB에 저장합니다.
5. 사용자 화면에서 변경된 언어별 콘텐츠를 표시합니다.

이 시나리오는 **요구사항·수용 기준**이며, 전체 시나리오에 대한 통합 테스트 통과를 의미하지 않습니다.

## 4. 구현 우선순위 및 범위 제외

**중점:** next-intl i18n, GSAP 연출, 반응형 UX, 프론트와 CMS 번역 연결.

**발표용 데모 범위 제외:** 동적 SSR, 실제 OAuth 로그인 완료, 실DB 상담/예약 저장, 실제 SMS/알림톡 발송, 백엔드 운영 SLA, 보안 심사 결과. 해당 기능이 화면에 보이더라도 운영 검증 완료로 소개하지 않습니다.
