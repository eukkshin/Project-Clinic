# 트러블슈팅 기록 — 실제 대화·오류 로그 기반

> **포트폴리오에서 가장 중요한 기술 문서.** 2026년 10~11월 성형외과 홈페이지 관련 여러 대화 세션의 오류·코드·디버깅 기록을 최대한 통합했습니다. 동일 문제의 서로 다른 가설과 수정 시도까지 구별합니다. **모든 과거 세션의 전체 원문 로그가 복원된 것은 아니므로 완전한 전수 목록이라고 주장하지 않습니다.**

## 기록 방식

- **확인된 원인:** 제공된 코드 또는 SQL/브라우저 오류로 직접 식별된 내용
- **유력 가설:** 코드와 증상이 일치하지만 최종 재현·검증 기록이 없는 경우
- **대응/검증:** 제안만 있었는지, 사용자가 실제 해결·적용을 확인했는지 구분
- **면접 포인트:** 특정 오류를 통해 이해한 시스템적 개념

> 문서의 코드 블록은 **개념 설명을 위한 축약 예시**일 수 있습니다. 실제 소스 전문이나 최종 배포본과 동일하다고 가정하면 안 됩니다.

## A. next-intl / 다국어 / 관리자 CMS (TS-01 ~ TS-08)

### TS-01 · `Couldn't find next-intl config file`

- **관찰:** Next.js 16.3.0(Turbopack)에서 `src/app/layout.tsx`의 `getLocale()` 호출 시 런타임 오류.
- **실제 메시지:** `Couldn't find next-intl config file. Please follow the instructions at https://next-intl.dev/docs/getting-started/app-router`
- **원인 영역:** `next-intl`의 요청 구성 파일 탐지와 Next.js 빌드 플러그인 연결.
- **대응:** App Router의 요청 구성과 Next 설정을 확인하고 경로를 맞추는 작업 진행.
- **검증 상태:** **사용자가 오류 해결을 직접 확인.** 다만 수정된 최종 파일 전문은 이 문서 작성 시점에 재검증되지 않음.
- **면접 포인트:** 서버 함수 `getLocale()`이 번역 설정과 연결되는 방식, App Router와 패키지 설정의 경계.

### TS-02 · 언어 드롭다운을 바꿔도 화면 문구가 변하지 않음

- **관찰:** 언어 선택 UI는 반응하지만 화면의 텍스트는 기존 언어로 유지.
- **원인 영역:** 선택 UI의 상태와 실제 `next-intl` locale/router context가 동기화되지 않거나 하드코딩 텍스트가 남는 문제.
- **대응:** locale 변경 경로, `useTranslations` 사용 위치, 메시지 키와 공통 컴포넌트의 상태를 점검.
- **검증 상태:** **사용자가 변경된 부분에서 번역 적용을 확인.** 전체 페이지 전수 검증과는 구분.
- **면접 포인트:** 프레젠테이션 상태 변경과 국제화 context 전환은 서로 다른 동작.

### TS-03 · 관리자에서 작성한 콘텐츠가 언어 전환 시 번역되지 않음

- **관찰:** 고정 UI 번역이 되더라도 CMS에서 직접 작성한 VLOG/안전 정보/푸터 등은 원문으로 남는 문제.
- **원인 영역:** `next-intl` 메시지 파일과 DB 기반 운영 콘텐츠는 데이터 원천과 업데이트 경로가 다름.
- **대응:** `VLOG`, `SAFETY`, `FOOTER`, `MAIN_VISUAL`, `CATEGORY`, `NAV_SETTING` 등 번역 유형을 확장하고 관리자 소스 조회/저장 경로 검토.
- **검증 상태:** **여러 유형에서 구현/수정 기록이 있으나 전체 번역 완료 증명은 없음.**
- **면접 포인트:** 국제화는 프론트 UI만이 아닌 API 데이터 모델과 관리 워크플로의 문제.

### TS-04 · Footer CMS API 500 + `ORA-00904`

- **관찰:** `GET /api/admin/content-i18n/sources/FOOTER` 호출 시 500.
- **실제 메시지:** `ORA-00904: invalid identifier` (`NAME` 컬럼 관련).
- **확인된 원인:** SQL에서 `FOOTER_SETTINGS.NAME`을 잘못 참조함. 실제 테이블에 인용부호가 적용된 소문자 `"name"` 등 식별자가 있어 대소문자 규칙 차이 발생.
- **대응:** 실테이블 컬럼 정의(`id`, `name`, `address`, `clinicName`, `phone`, `email`, `locationUrl`, CLOB 컬럼 등)를 기준으로, SQL에서 `"id"`, `"name"` 등을 정확히 참조하거나 적절한 alias를 사용하도록 수정.
- **검증 상태:** **원인 및 수정 방향이 코드/스키마 기록으로 확인됨.** 최종 배포 API 재검증은 별도.
- **면접 포인트:** Oracle의 unquoted 대문자 정규화 vs quoted 대소문자 구분, 직접 SQL과 ORM 매핑 일치.

### TS-05 · CMS 번역 저장 시 `ORA-02290 CK_CMS_I18N_TYPE`

- **관찰:** FOOTER 등 새 번역 유형을 저장할 때 INSERT/UPDATE 실패.
- **실제 메시지:** `ORA-02290: check constraint (CK_CMS_I18N_TYPE) violated`
- **확인된 원인:** 백엔드는 새 `ENTITY_TYPE`을 처리하지만 DB 체크 제약의 허용 값에 새 유형이 없음.
- **대응:** 기존 허용값을 보존하면서 `VLOG`, `SAFETY`, `FOOTER`, `MAIN_VISUAL`, `CATEGORY`, `NAV_SETTING` 등 필요한 유형을 제약조건에 반영.
- **검증 상태:** **제약조건 확장 작업 기록 확인.** 해당 모든 유형의 저장·조회 성공 테스트는 별도.
- **면접 포인트:** 프론트 enum, 서버 DTO, DB constraint는 공동 스키마 계약.

### TS-06 · Hero 문구 등 정적 컴포넌트의 번역 누락

- **관찰:** Hero 설명 문구, 커뮤니티 콘텐츠, VLOG 섹션 소개 문구가 언어 전환 후도 한국어인 영역 확인.
- **대응:** 텍스트가 어디에 하드코딩되어 있는지와 `useTranslations` 네임스페이스 연결 여부를 페이지·컴포넌트 단위로 확인.
- **검증 상태:** **누락 보고와 수정 요청 기록.** 모든 문구 최종 수정 확인은 아님.
- **면접 포인트:** UI가 정상 동작해도 i18n coverage는 별도 검증 대상.

### TS-07 · 지도에서 보기/서비스 레이블 번역 누락

- **관찰:** 지도 관련 `자세히 보기`, Naver/Kakao/Google 선택 UI에 번역 대상 문구가 남음.
- **대응:** 지도 SDK 제어 로직과 화면 문구를 분리하고 UI 메시지는 `next-intl`으로 처리하는 방향 검토.
- **검증 상태:** **번역 대상 식별 기록.** 전체 적용 여부 별도 확인 필요.
- **면접 포인트:** 외부 SDK와 무관한 화면 문구는 UI 번역 레이어에서 관리.

### TS-08 · 다국어 페이지 빌드·경로의 모드 차이

- **관찰:** SSR용 `getLocale()`·요청 헤더 접근, locale별 경로와 정적 export가 충돌할 수 있음.
- **원인 영역:** 서버 요청 문맥이 존재하는 실행 모드와 사전 생성된 HTML 배포의 능력 차이.
- **대응:** 정적 export 조건에서 서버 전용 데이터 조회 경로를 분리하고 빌드 시 동적 의존 제거.
- **검증 상태:** **분리 코드 및 정적 빌드 수행 기록 확인.** 전 경로 호환성 추가 확인 필요.
- **면접 포인트:** 국제화 라우팅 설계는 선택한 렌더링/배포 전략과 결합돼 있음.

## B. GSAP / React DOM / Intro (TS-09 ~ TS-14)

### TS-09 · 페이지 전환 시 `NotFoundError: removeChild`

- **관찰:** 로그인 등 다른 경로로 이동할 때 오류.
- **실제 메시지:** `Failed to execute 'removeChild' on 'Node': The node to be removed is not a child of this node.`
- **유력 가설 ①:** 지도 SDK가 컨테이너 내부 DOM을 변경하고 정리 시 `replaceChildren()` 등으로 React의 예상 DOM 구조를 깨뜨렸을 가능성.
- **유력 가설 ②:** `ScrollTrigger`의 `pin:true`가 만드는 `pin-spacer`와 React 언마운트의 순서 충돌.
- **대응:** 지도 강제 DOM 삭제 코드 제거 검토, 지도 컴포넌트 분리 재현, GSAP 컨텍스트/ScrollTrigger `revert()`를 언마운트 전 수행하도록 정리 순서 검토.
- **검증 상태:** **오류 관찰은 확정, 단일 근본 원인은 확정되지 않음.** 두 후보를 하나의 '확정 해결' 사례로 과장하지 않음.
- **면접 포인트:** React의 선언적 DOM 소유권과 외부 라이브러리의 명령형 DOM 조작 충돌.

### TS-10 · ScrollTrigger `pin-spacer` 복원 문제

- **관찰:** 스크롤 고정 연출이 있는 영역에서 이탈/언마운트 시 DOM 정리 문제가 발생할 수 있음.
- **기술 분석:** `pin:true`는 요소의 위치를 유지하기 위해 별도 래퍼와 인라인 스타일을 조작함. 트리거가 살아 있는 상태에서 React가 해당 영역을 제거하면 구조 충돌 가능.
- **대응:** `gsap.context()`와 cleanup의 `revert()`, 필요 시 레이아웃 이펙트, 트리거 수명 주기 범위 축소 검토.
- **검증 상태:** **진단 및 해결 전략 제안 기록.** 완전한 확정 원인으로 표현하지 않음.
- **면접 포인트:** 애니메이션의 생성과 제거는 한 쌍의 자원 관리.

### TS-11 · Intro 새로고침 시 화면이 번쩍였다가 사라짐

- **관찰:** F5 새로고침 순간 Intro가 잠깐 그려진 뒤 메인 페이지로 즉시 전환.
- **확인된 원인:** 정적 빌드에서 `shouldPlay=true`이므로 HTML에 Intro가 포함됨. 클라이언트의 `useEffect`가 `performance.getEntriesByType('navigation')[0].type === 'reload'`를 감지한 뒤 `finish()`를 호출해 숨김.
- **대응:** 정적 모드의 초기 `visible`을 `false`로 두어 서버 HTML 단계부터 오버레이를 출력하지 않고, 마운트 이후 진입 조건이 맞을 때만 표시하는 구조로 변경 검토.
- **검증 상태:** **증상과 원인은 제공 코드로 확정.** 최종 진입 정책의 모든 경로 검증은 별도.
- **면접 포인트:** 서버 HTML과 클라이언트 이펙트 실행 간 시차, 화면 플래시(FOUC 유사 현상), 하이드레이션 전후의 초기 상태.

### TS-12 · Intro 외부 링크 진입으로 제한하자 직접 접속에서 미재생

- **관찰:** 새로고침 플래시를 막은 이후 Intro가 더 이상 보이지 않는다고 보고.
- **확인된 원인:** `document.referrer`가 비어 있으면 `return`하는 조건 때문에 주소 직접 입력·북마크 진입은 재생 대상에서 빠짐.
- **대응:** `PerformanceNavigationTiming.type`으로 `navigate`/`reload`/`back_forward`를 구분하고, `document.referrer`가 있는 경우에만 same-origin 여부를 검사하는 로직 검토.
- **제약:** Next.js SPA 내부 이동은 최초 문서의 navigation entry만으로 완벽하게 분리할 수 없음. 브라우저 referrer 정책에 따라 외부 링크도 referrer가 없을 수 있음.
- **검증 상태:** **문제 원인 확인, 대안 설계 제시. 최종 성공 여부 미확인.**
- **면접 포인트:** Navigation Timing API, 브라우저 referrer privacy, SPA navigation, UI 상태 초기화.

### TS-13 · 정적 export에서 외부 진입 헤더 기반 Intro 판별 불가능

- **관찰:** 서버 버전 `page.tsx`는 `headers()`, `referer`, `sec-fetch-site` 등을 활용했지만 발표용 정적 빌드에서는 같은 판단을 할 수 없음.
- **확인된 원인:** `output: export`는 요청별 서버 렌더링을 수행하지 않음. `PRESENTATION_EXPORT=1`(문서상 익명화한 환경 변수명) 시 서버 전용 분기를 건너뛰도록 구현돼 있었고, 이 때문에 초기에는 `shouldPlay=false`로 Intro 자체가 미실행.
- **대응:** 정적 모드 분기 설정, 클라이언트 진입 조건 별도 관리.
- **검증 상태:** **환경 분기 원인 확인.**
- **면접 포인트:** SSR/SSG/정적 export 간 차이와 환경 의존 UI 기능의 설계.

### TS-14 · Intro와 Hero 애니메이션 시작 시점 동기화

- **관찰:** Hero가 `introPlaying`을 기준으로 진입 애니메이션 준비 상태를 제어하고 `intro-finished` 이벤트를 기다림.
- **위험:** Intro의 초기 표시 조건과 Hero의 `introPlaying` prop이 다르면 기다릴 필요 없는 이벤트를 기다리거나 두 연출이 겹칠 수 있음.
- **대응:** `intro-finished` 커스텀 이벤트, Intro DOM 존재 여부 확인 로직, 상태 전환 시점 점검.
- **검증 상태:** **관련 코드 확인, 완전한 통합 동기화 검증은 미확인.**
- **면접 포인트:** 독립 컴포넌트 사이의 비동기 이벤트 계약과 탈출 조건.

## C. 이미지 / 지도 / 스크롤 / 빌드 (TS-15 ~ TS-21)

### TS-15 · `next/image`의 `fill` 부모 포지셔닝 경고

- **관찰:** `SafetySlider.tsx`의 `<Image fill>` 관련 경고.
- **확인된 원인:** 이미지 부모 요소 `MobilePicture`에 `position: relative`가 모바일 미디어쿼리에서만 적용돼 특정 뷰포트에서 유효한 positioning context를 제공하지 않음.
- **대응:** 기본 스타일에 `position: relative`를 부여해 `fill`의 기준 요소 확보.
- **검증 상태:** **코드 수준 원인·수정안 확인.** 최종 전 뷰포트 경고 해소 확인은 별도.
- **면접 포인트:** CSS containing block과 Next.js 이미지 레이아웃.

### TS-16 · LCP 이미지의 로딩 전략 경고

- **관찰:** 화면 상단 이미지에 loading/eager·우선순위 관련 안내 등장.
- **원인 영역:** 중요 이미지의 로딩 시점이 최초 화면 표시 속도에 영향을 줌.
- **대응:** 첫 화면의 실제 LCP 이미지에 한해 우선 로딩을 적용하고, 화면 밖 이미지는 지연 로딩 유지하는 방식 검토.
- **검증 상태:** **경고 분석 기록.** 최종 Web Vitals 수치 측정은 없음.
- **면접 포인트:** 모든 이미지에 priority를 주는 것이 아니라 LCP 후보를 구별해야 함.

### TS-17 · 지도 SDK 타입 정의에 없는 메서드 사용

- **관찰:** Kakao Map 관련 `map.setMaxLevel(10)`, `map.setMinLevel(1)`, `map.setZoomable(false)` 줄의 TypeScript 오류 보고.
- **원인 영역:** 설치된 SDK 타입 선언과 실제/가정한 메서드 API의 불일치. 특히 일부 level 제약 메서드는 다른 지도 API와 혼동하기 쉬움.
- **대응:** 지원되는 생성 옵션/메서드만 사용하도록 API 타입·공식 문서 확인, 불필요한 메서드 호출 제거 검토.
- **검증 상태:** **타입 오류 보고 및 대응 제안 기록.** 당시 정확한 버전·타입 정의 기반의 최종 적용은 미확인.
- **면접 포인트:** SDK의 런타임 기능과 TypeScript 선언 파일을 구별하는 습관.

### TS-18 · 지도 초기화/해제 코드가 React DOM을 직접 비움

- **관찰:** 지도 관련 코드의 `container.replaceChildren()`가 페이지 전환 시 DOM 충돌 원인 후보로 지적.
- **대응:** React/지도 SDK가 관리하는 자식 노드를 강제로 비우지 않도록 cleanup 수정 제안. 지도 컴포넌트 경계 분리 및 재마운트 테스트.
- **검증 상태:** **유력 원인 후보, 단독 재현 확인은 없음.**
- **면접 포인트:** 외부 SDK cleanup에서 DOM 소유권을 존중해야 함.

### TS-19 · 지도에서 일반 스크롤이 막히는 문제

- **관찰:** 지도 영역의 휠 이벤트 관련 상호작용 문제.
- **원인 영역:** 스크롤 라이브러리와 지도 컴포넌트의 `data-lenis-prevent` 설정이 일반 페이지 스크롤을 막을 수 있음.
- **대응:** 속성 제거를 포함해 지도 상호작용과 페이지 스크롤의 우선권 재조정.
- **검증 상태:** **코드 수정 기록, 전 브라우저 재검증 미확인.**
- **면접 포인트:** 임베디드 인터랙티브 위젯과 페이지 스크롤 간 UX 충돌.

### TS-20 · 지도 SDK 로딩과 탭 전환 안정성

- **관찰:** 외부 지도 3종(Naver/Kakao/Google)을 페이지에 동시에 포함할 때 초기 로딩과 전환 관리 필요.
- **대응:** `IntersectionObserver`(`rootMargin: "450px 0px"`)로 영역 근접 시 로드, keyed `SdkMap`으로 전환 시 재마운트 경계 설정, 외부 링크 `noopener noreferrer` 적용 기록.
- **검증 상태:** **구현 코드 기록 확인.**
- **면접 포인트:** 성능 최적화는 사용 시점 지연과 리소스 해제의 균형.

### TS-21 · `/favicon.ico` 404 및 Turbopack workspace 경고

- **관찰:** favicon 404 및 `Next.js ignored package-lock.json ...`, `inferred your workspace root` 빌드 경고.
- **원인 영역:** favicon 파일 부재, 상위/하위 디렉터리에 여러 lockfile이 존재해 Turbopack이 루트를 다르게 추론함.
- **대응:** `src/app/favicon.ico` 또는 `public/favicon.ico` 추가, 모노레포 경계·lockfile 정리 또는 `turbopack.root` 명시 검토.
- **검증 상태:** **경고 원인 확인, 실제 적용 여부 일부 미확인.**
- **면접 포인트:** 런타임 오류와 빌드 경고를 구분하고 빌드 도구의 탐색 범위를 명확히 해야 함.

## D. 로그인 / 인증 / React 조건식 (TS-22 ~ TS-26)

### TS-22 · 헤더·푸터가 전체 페이지에서 사라지는 조건식 버그

- **관찰:** 로그인/회원 관련 페이지를 조정하던 중 Header/Footer 및 로그인 모달 호스트가 예상치 않게 사라짐.
- **확인된 원인:** 아래 표현식의 마지막 항이 비교식이 아닌 **항상 참인 문자열 리터럴**.

```tsx
// 잘못된 예: 마지막 문자열은 truthy
const isAuthPage =
  pathname === "/register/login" ||
  pathname === "/register/terms" ||
  "/register/social";
```

- **대응:** `authPages.includes(pathname)` 형태의 명시적 비교, locale/basePath 접두사와 trailing slash 정규화 검토.
- **검증 상태:** **원인 코드 명확히 확인, 수정 안내 기록.** 최종 배포 전 화면 확인 필요.
- **면접 포인트:** JS truthy/falsy와 라우트 조건식, 공통 레이아웃의 영향 범위.

### TS-23 · 회원가입·비밀번호 재설정 후 로그인 모달 대신 별도 로그인 페이지로 이동

- **관찰:** 가입 완료/이전 버튼, 비밀번호 찾기·재설정, 소셜 가입 이후 `/register/login` 화면으로 이동.
- **원인 영역:** 여러 컴포넌트에 하드코딩된 로그인 링크가 남아 있고, 원래 UI 정책인 **홈으로 이동 후 전역 로그인 모달 열기**와 불일치.
- **대응:** 기존 `openLoginModal` 유틸리티/`AuthModalHost` 이벤트 사용, 필요 시 `sessionStorage`의 일회성 복귀 플래그로 리다이렉트 후 모달 열기 검토.
- **검증 상태:** **사용자가 후속 작업으로 명시적으로 보류한 항목. 완료라고 표현 금지.**
- **면접 포인트:** 하나의 사용자 여정에 흩어진 링크를 단일 내비게이션 계약으로 통합해야 함.

### TS-24 · 로그인하지 않은 사용자의 `/api/mypage/me` 401

- **관찰:** `Header.tsx`가 `credentials: 'include'`로 사용자 정보 API를 요청했으나 401 반환.
- **분석:** 미인증 상태라면 401은 정상적인 HTTP 인증 응답일 수 있음. JS 런타임 오류와 혼동하면 안 됨.
- **대응:** 비로그인 상태에서 사용자 정보·로컬 캐시를 비우고 UI를 비회원 모드로 유지하도록 처리, 필요 시 불필요한 요청과 중복 요청 점검.
- **검증 상태:** **응답·코드 흐름 확인.** 인증 방식 자체 변경은 확인되지 않음.
- **면접 포인트:** HTTP 오류 상태 처리와 실제 버그 분류 능력.

### TS-25 · Footer 데이터가 null일 때 `companyInfo` 접근 TypeError

- **관찰:** `Header.tsx`에서 Footer 설정 API 응답을 읽는 중 페이지 오류.
- **실제 메시지:** `Cannot read properties of null (reading 'companyInfo')`
- **원인:** `footer.value.data.data`가 null인데 `.companyInfo`를 접근함. `companyInfo?.phone`의 옵셔널 체이닝은 **상위의 `data`가 null인 것까지 보호하지 못함.**
- **대응:** `footer.value.data.data?.companyInfo?.phone?.trim() ?? ''`처럼 nullable 경로 전체 점검, API 실패 시 fallback UI 고려.
- **검증 상태:** **오류 줄과 null 원인 확인, 수정 방향 제시.** 최종 반영 확인은 별도.
- **면접 포인트:** Optional chaining을 적용해야 할 정확한 객체 경계.

### TS-26 · 소셜 로그인 UI는 있지만 실제 OAuth 연동 환경은 미구축

- **관찰:** 카카오·네이버·구글 버튼을 `map()`으로 표시하며 `/api/auth/social/{provider}/start`로 이동하도록 구성. 발표용 정적 페이지에서는 OAuth 정상 동작이 보장되지 않음.
- **대응:** `NEXT_PUBLIC_SOCIAL_AUTH_ENABLED` 플래그, 공급자별 아이콘(`react-icons`), 번역 키, 클릭 동작 재사용. 공급자 콘솔 앱·콜백 URL·HTTPS·세션/쿠키 환경은 실제 연결 전 별도 설정 필요.
- **검증 상태:** **UI 코드 확인, 운영 OAuth 성공 미확인.**
- **면접 포인트:** 기능의 화면 표시와 실제 서버 인증 완료는 별개의 검증 단계.

## E. OracleDB / 예약·상담 / 서버 API (TS-27 ~ TS-31)

### TS-27 · 마이페이지 예약 조회 `ORA-00942`

- **관찰:** `GET /api/mypage/reservations`에서 DB 조회 실패, 쿼리가 `CUSTOMER_RESERVATION_TB`를 참조함.
- **실제 메시지:** `ORA-00942: table or view does not exist`
- **원인 후보:** 존재하는 예약 테이블과 TypeORM Entity의 테이블명 매핑이 불일치하거나 현재 DB 스키마/권한이 다름. 당시 `RESERVATION_TB`와의 이름 불일치가 주요 후보.
- **대응:** 실제 테이블/사용자/권한 확인, Entity `tableName`과 쿼리 대상 일치 여부 검토.
- **검증 상태:** **오류 관찰, 원인 후보 특정. 수정 완료 증거 없음.**
- **면접 포인트:** ORM은 실DB 스키마를 자동으로 사실처럼 보장하지 않음.

### TS-28 · 예약 관련 테이블·인덱스 생성 중 `ORA-00955`

- **관찰:** `RESERVATION_BLOCK_TB`, `IX_RESERVATION_BLOCK_DATE`, `RESERVATION_BOOKING_LOCK_TB` 등을 생성할 때 객체명 중복 발생.
- **실제 메시지:** `ORA-00955: name is already used by an existing object`
- **확인된 원인 영역:** 기존 객체가 존재하는 환경에서 같은 DDL을 재실행.
- **대응:** Oracle 데이터 딕셔너리로 기존 객체 확인, DROP/CREATE를 무조건 반복하지 않고 변경 스크립트를 멱등성 있게 작성하거나 마이그레이션 도입 검토.
- **검증 상태:** **오류와 중복 개연성 확인, 수정안 기록.**
- **면접 포인트:** DB 설치 스크립트의 재실행 가능성과 마이그레이션 관리.

### TS-29 · 예약 잠금 레코드 삽입 `ORA-00001`

- **관찰:** 예약 잠금 테이블에 `lock_id=1` 등 기존 키와 중복되는 데이터 INSERT 시 실패.
- **실제 메시지:** `ORA-00001: unique constraint violated`
- **확인된 원인 영역:** 기존 고유키 또는 PK 값 중복.
- **대응:** 초기 데이터 중복 확인, ID 생성 방식 및 INSERT/UPSERT 전략 점검.
- **검증 상태:** **오류 기록 확인.**
- **면접 포인트:** 중복 방지는 애플리케이션 체크뿐 아니라 DB 유니크 제약으로 보장.

### TS-30 · 예약 availability/admin API 500

- **관찰:** 예약 가능 시간 조회와 관리자 예약 API에서 500 오류 보고.
- **원인 후보:** 엔티티 등록, 실제 Oracle 컬럼/테이블 정의, 쿼리 매핑, 예약 관련 스키마 부족 가능성.
- **대응:** API 스택 트레이스와 SQL 오류를 기준으로 테이블/컬럼/엔티티 비교하는 순서 제안.
- **검증 상태:** **에러 발생 확인, 단일 근본 원인 미확정.**
- **면접 포인트:** 500만으로 원인을 단정하지 않고 백엔드 로그와 DB 단계로 좁혀야 함.

### TS-31 · OracleDB CLOB 및 CMS 스키마 타입 관리

- **관찰:** Footer 설정 등의 `schedules`, `familySites`는 CLOB 컬럼이며 코드·SQL 작성 과정에서 타입/식별자 문제가 발생할 수 있는 구조.
- **대응:** Entity/SQL/JSON 응답 직렬화 경계, nullable 컬럼, CLOB 읽기/쓰기 방식을 실테이블에 맞게 처리하도록 설계 검토.
- **검증 상태:** **스키마 정보 확인, 독립적인 CLOB 런타임 오류가 확정된 것은 아님.**
- **면접 포인트:** DB 데이터 타입과 API 응답 형태의 변환 경계.

## F. Next.js 정적 export / Cafe24 / 배포 (TS-32 ~ TS-35)

### TS-32 · 서버 전용 API 사용 시 정적 빌드 실패

- **관찰:** 발표용 빌드가 원본처럼 `headers()` 등 요청 의존 기능을 수행하려고 하면 `output: export`와 충돌.
- **확인된 원인:** 동적 서버 요청 데이터를 빌드 단계의 사전 생성 HTML에서 계산할 수 없음.
- **대응:** `PRESENTATION_EXPORT=1`(문서상 익명화한 환경 변수명) 플래그로 서버 요청·DB 초기 데이터 조회 경로를 분기. 예: `getInitialHeroSlides` 호출 대신 정적 모드에서는 빈 초기 데이터 사용.
- **검증 상태:** **빌드 환경 분기 코드 및 성공을 전제로 한 배포 수행 기록.**
- **면접 포인트:** 빌드 성공을 위해 서버 기능을 정적 대체한 것은 기능 동등성 확보와 다른 문제.

### TS-33 · Next.js 16 정적 출력의 RSC `.txt` 파일 경로 문제

- **관찰:** 다중 경로를 정적 export해 FTP 업로드할 때 RSC 관련 `.txt` 산출물의 파일 경로가 브라우저 요청 경로와 달라 정적 페이지 전환이 실패할 수 있음.
- **대응:** `out/` 아래 `__next...`로 시작하는 경로 세그먼트를 요청하는 점 구분된 파일명으로 복사하는 PowerShell 경로 보정. 예: `about/brand` 라우트의 `__next.about.brand.__PAGE__.txt` 존재 확인.
- **검증 상태:** **보정 과정과 배포 지시 기록. 개별 라우트의 성공 여부는 업로드 후 검증 필요.**
- **면접 포인트:** 정적 호스팅의 URL 매핑·출력 자산 경로는 프레임워크 런타임과 별개로 점검해야 함.

### TS-34 · FTP 업로드 경로와 basePath 자산 연결

- **관찰:** `/group/three/1/` 같은 하위 경로에 배포하면서 이미지/스크립트 경로가 루트 기준으로 계산되면 404 가능.
- **대응:** 정적 export 결과 `out`의 **내용물**을 서버의 대상 경로에 배치, `next/image` 정적 이미지 경로와 basePath 확인, 브라우저 강력 새로고침.
- **검증 상태:** **Cafe24 업로드 워크플로 확인, 모든 자산 최종 검증 미확인.**
- **면접 포인트:** URL basePath와 실제 파일 시스템 경로 사이의 일치.

### TS-35 · 정적 데모에서 로그인/상담/예약이 작동하지 않음

- **관찰:** 정적 사이트는 렌더링되지만 REST API·DB·OAuth 의존 기능은 별도 서비스 없이 수행할 수 없음.
- **확인된 원인:** 정적 export 결과물은 HTML/CSS/JS 자산이며 Express 서버와 OracleDB를 포함하지 않음.
- **대응:** 데모 기능 범위를 문서에 분명히 표기, 동적 기능을 검증하려면 별도 백엔드 배포·HTTPS·CORS·쿠키/콜백 설정 필요.
- **검증 상태:** **아키텍처 제약 확정. 운영 백엔드 배포는 별개.**
- **면접 포인트:** '정적 배포 성공'과 '풀스택 운영 완료'의 엄밀한 구분.

## G. 기타 개발 환경·라우팅 점검 (TS-36 ~ TS-37)

### TS-36 · 컴포넌트 경로/모듈을 찾지 못하는 오류

- **관찰:** `Cannot find module` 오류와 `about/location/LocationFlat.styles` 등 경로 관련 문제 다수 보고.
- **원인 후보:** 파일 이동·이름 변경·경로/대소문자 변경이 import와 맞지 않거나 일부 수정본에 파일 누락.
- **대응:** 실제 파일 시스템과 `@/` alias, 상대 경로, 파일명/확장자 확인을 통해 전체 참조 동기화.
- **검증 상태:** **문제 보고 및 전수 점검 요청 기록.** 모든 파일의 최종 수정 확인 없음.
- **면접 포인트:** 컴포넌트 리팩터링은 사용처 import 경로와 빌드 결과까지 관리해야 함.

### TS-37 · Git 줄바꿈 정규화 경고

- **관찰:** `git add .` 때 `LF will be replaced by CRLF the next time Git touches it` 경고 발생.
- **원인 영역:** Windows Git 자동 줄바꿈 정책과 저장소의 파일 줄바꿈 형식 불일치.
- **대응:** `.gitattributes`, Git `core.autocrlf`, 에디터 줄바꿈 설정을 일관되게 관리하는 방향 점검.
- **검증 상태:** **경고 발생 확인, 실제 설정 수정 여부 미확인.**
- **면접 포인트:** 팀 협업에서 의미 없는 diff와 플랫폼별 줄바꿈 문제를 예방.

### STAR 답변 예시 ① — CMS 다국어 저장 실패

- **상황(S):** 여러 콘텐츠 유형을 다국어로 관리하도록 확장하는 중 새 FOOTER 콘텐츠 번역 저장 API가 실패했습니다.
- **과제(T):** 화면의 번역 키 수정으로 끝내지 않고 데이터 저장 단계까지 기능을 연결해야 했습니다.
- **행동(A):** `ORA-02290 CK_CMS_I18N_TYPE` 로그를 확인해 번역 콘텐츠 타입의 신규 값이 DB 제약조건의 허용 목록에 없는 것을 확인하고, 기존 타입을 보존해 스키마 변경 범위를 검토했습니다.
- **결과(R):** 장애 원인이 UI가 아니라 DB 스키마 계약에 있다는 점을 규명하고 수정 방향을 마련했습니다. **모든 CMS 유형의 저장·조회 회귀 테스트가 완료됐다는 주장은 하지 않습니다.**

### STAR 답변 예시 ② — Intro가 새로고침마다 번쩍임

- **상황(S):** 정적 배포본에서 Intro가 새로고침 순간 표시됐다가 즉시 사라졌습니다.
- **과제(T):** 새로고침에서는 Intro를 실행하지 않되 첫 진입 동작은 유지해야 했습니다.
- **행동(A):** 정적 HTML의 `shouldPlay` 초기값과 클라이언트 `useEffect`에서 `navigation.type === 'reload'` 후 `finish()`를 호출하는 코드를 대조했습니다. 초기 렌더와 클라이언트 판별의 시차를 원인으로 특정했습니다.
- **결과(R):** 초기 표시 상태부터 조건을 제어해야 함을 확인했습니다. 이후 `referrer` 기반 접근이 직접 입력 진입을 막는 한계도 찾아 Navigation Timing을 포함한 보완을 검토했습니다. **최종 모든 브라우저/경로에서 성공했다는 근거는 아직 없습니다.**

### STAR 답변 예시 ③ — 화면 전환 중 DOM 오류

- **상황(S):** 지도나 스크롤 고정 구간에서 다른 페이지로 이동할 때 `removeChild` 예외가 발생했습니다.
- **과제(T):** React 자체 오류인지 명령형 UI 라이브러리의 후처리 문제인지 분리해야 했습니다.
- **행동(A):** 지도 SDK의 `replaceChildren()`와 GSAP의 `pin-spacer`를 각각 원인 후보로 두고, 컴포넌트 단위 제거·재현·cleanup 호출 순서 점검을 제안했습니다.
- **결과(R):** React가 관리하는 DOM과 외부 라이브러리의 DOM 변경을 조심해야 한다는 설계 원칙을 얻었습니다. **원인 확정과 최종 수정 완료는 확인되지 않은 상태**이므로 면접에서도 진단 과정으로 설명합니다.

## 문서 작성의 신뢰도

- **확정적 표현이 가능한 것:** 실제 오류 문구가 공유된 사례, 명백한 JS 조건식 실수, 정적 export의 서버 기능 부재, `shouldPlay=true` + `reload`의 플래시 원인.
- **조심해서 설명할 것:** DOM `removeChild`의 단일 원인, 지도 타입 오류의 정확한 SDK 버전, 예약 API 500의 실제 SQL 원인, 모든 i18n/GSAP 테스트 완료 여부.
- **검증에 필요한 자료:** 현재 브랜치 소스, 빌드/실행 로그, 스크린샷, 재현 절차, Git 커밋 이력.
