# 면접 예상 질문 · 기술 답변 가이드

> 답변은 **실제 구현·해결 경험의 범위에서만** 사용합니다. “완성했습니다”보다 “무엇을 확인했고, 어떻게 설계했으며, 무엇이 남았는지”를 분명히 설명합니다.

### Q1. 이 프로젝트에서 가장 집중한 기술은 무엇인가요?

**A.** `next-intl` 기반의 5개 언어 지원과 GSAP/ScrollTrigger 인터랙션입니다. 다국어는 공통 UI 번역뿐 아니라 관리자에서 수정하는 CMS 콘텐츠까지 다뤘고, GSAP은 Intro/Hero/스크롤 연출과 함께 React 생명주기 충돌이나 새로고침 시 초기 상태 문제를 분석했습니다.

### Q2. `next-intl`을 단순 JSON 교체보다 어떻게 활용했나요?

**A.** `useLocale`, `useTranslations`로 현재 locale과 UI 메시지를 연결하고, 서버 측 locale 처리 및 페이지 경로도 고려했습니다. 운영 콘텐츠는 JSON 번역과 달리 DB에서 관리되므로 별도 번역 조회/저장 계약이 필요했습니다.

### Q3. CMS 번역에서 가장 어려운 문제는?

**A.** `ORA-02290 CK_CMS_I18N_TYPE`입니다. 화면에 신규 콘텐츠 유형을 추가해도 Oracle 체크 제약조건에 허용되지 않으면 저장이 실패했습니다. 이를 통해 프론트·API·DB가 동일한 데이터 유형 계약을 지켜야 함을 배웠습니다.

### Q4. `ORA-00904`는 왜 발생했나요?

**A.** Footer 설정 테이블의 컬럼 식별자와 SQL의 컬럼 참조가 맞지 않았습니다. Oracle은 따옴표 없이 생성한 식별자와 인용 식별자의 대소문자 처리 규칙이 달라, 실제 테이블 정의와 쿼리를 대조해야 했습니다.

### Q5. GSAP 대신 CSS transition으로 충분하지 않았나요?

**A.** 단일 hover 등은 CSS가 효율적입니다. 이 프로젝트의 Intro처럼 여러 요소의 시작 시점, 타이핑 시작, 종료, Skip, 스크롤 구간의 pin 연출을 함께 제어해야 하는 곳에는 타임라인 모델이 적합했습니다.

### Q6. `useRef`는 왜 사용했나요?

**A.** DOM 요소와 GSAP Timeline 같은 변경 가능한 객체를 렌더링 횟수와 독립적으로 유지하기 위해 사용했습니다. 애니메이션의 중단/정리 시 정확한 대상에 접근하는 데 필요했습니다.

### Q7. `useEffect`의 cleanup은 왜 중요했나요?

**A.** GSAP Timeline, keydown 이벤트, ScrollTrigger pin 등이 컴포넌트 언마운트 이후에도 남으면 스타일·DOM 구조나 스크롤 상태에 문제가 생길 수 있습니다. 생성한 부수효과를 해제 시점에 복원해야 합니다.

### Q8. Intro가 새로고침 때 깜빡였던 이유는?

**A.** 정적 HTML에서 Intro를 먼저 렌더링했지만, 마운트 후 `useEffect`가 새로고침임을 파악하고 종료시켰습니다. 즉 클라이언트에서 판단하기 전에 HTML이 이미 보인 것입니다. 이를 해결하려면 초기 HTML의 표시 정책부터 조정해야 했습니다.

### Q9. referrer만으로 첫 방문을 판단할 수 있나요?

**A.** 완벽하지 않습니다. 주소 직접 입력/북마크에서는 referrer가 비어 있을 수 있고, 외부 링크에서도 브라우저 정책이 referrer를 숨길 수 있습니다. `PerformanceNavigationTiming.type`도 SPA 내부 라우팅 전체를 구분하지 못하므로 추가적인 라우터 수준 추적이 필요합니다.

### Q10. `removeChild` 오류의 원인을 확정했나요?

**A.** 단일 원인으로 확정하지는 않았습니다. 지도 SDK가 직접 자식을 제거하는 cleanup과 ScrollTrigger pin-spacer가 React의 언마운트와 충돌하는 경우를 후보로 두고 원인 격리와 cleanup을 검토했습니다. 확인되지 않은 가설을 해결 완료라고 주장하지 않겠습니다.

### Q11. `next/image fill`의 부모에 `position:relative`가 왜 필요한가요?

**A.** fill 방식 이미지가 부모 컨테이너의 크기·위치를 기준으로 배치되기 때문입니다. 특정 미디어쿼리에서만 position이 설정되어 있으면 다른 뷰포트에서는 올바른 기준을 잃을 수 있습니다.

### Q12. Next.js 서버 버전과 정적 export의 차이는?

**A.** 요청별 서버 실행이 가능한 환경에서는 요청 헤더·인증/DB 조회 등에 접근할 수 있습니다. 정적 export는 빌드 단계에서 HTML을 생성하므로 방문자별 `headers()`나 서버 데이터 조회가 같은 방식으로 작동하지 않습니다. 발표용 정적 데모와 실제 서비스의 기능 범위를 분리했습니다.

### Q13. 왜 Oracle을 사용했나요?

**A.** 이 프로젝트의 주어진 데이터 환경에서 Oracle을 사용했고 TypeORM 매핑과 일부 직접 SQL을 다뤘습니다. 실제 오류를 통해 ORM 설정만이 아니라 테이블·컬럼·제약조건을 직접 검토해야 한다는 점을 배웠습니다.

### Q14. 팀 프로젝트에서 어떤 부분을 직접 담당했나요?

**A.** 실제 담당 범위에 맞게 답변을 조정해야 합니다. 이 문서만으로 사용자 개인의 단독 구현 기여율, 팀원별 담당 영역을 확정할 수 없습니다. Git 커밋과 발표 자료를 기준으로 직접 구현·수정·검증한 영역을 구체적으로 제시하는 것이 좋습니다.

### Q15. AI 도움을 받은 개발 경험은 어떻게 설명하면 좋을까요?

**A.** “AI를 코드 초안과 오류 원인 탐색의 도구로 활용했고, 실제 에러 로그·타입·라우팅·DB 스키마를 확인하며 수정 방향과 동작을 검증했습니다. 특히 제안받은 Intro 수정이 추가 문제를 만든 경험을 통해 AI 제안을 그대로 적용하기보다 재현 조건과 회귀 테스트가 필수임을 배웠습니다.” 실제로 본인이 수행한 검증만 이야기합니다.

### Q16. 프로젝트에서 성장했다고 생각하는 부분은?

**A.** 프론트 구현을 넘어 국제화, DB 스키마, 명령형 애니메이션과 React 생명주기, 정적 배포 제약을 연결해서 문제를 보는 시각을 얻었습니다. 동시에 수정 후 다른 진입 경로에 영향을 미치는 회귀 문제를 경험해 테스트 기준을 먼저 정할 필요성을 배웠습니다.
